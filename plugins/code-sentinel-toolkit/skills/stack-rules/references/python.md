# Python

Covers Python 3 services, workers, CLIs and libraries. `pyproject.toml` builds (uv, poetry,
hatch, setuptools).

## Naming
- Modules, functions, variables `snake_case`; classes `PascalCase`; module-level constants
  `UPPER_SNAKE_CASE`.
- Booleans take an `is_`/`has_`/`should_`/`can_` prefix.
- A single leading underscore marks module- or class-private names; flag new public API
  that is only meant for internal use.

## Typing
- Type hints on every public function: parameters and return type. Missing hints are the
  equivalent of implicit `any`.
- `Any` (and bare `dict` / `list` in public signatures) is the escape hatch: flag it, suggest
  `TypedDict`, a dataclass, a Pydantic model or a `Protocol`.
- `# type: ignore` / `# pyright: ignore` without an error code and a reason.
- `Optional[X]` / `X | None` used without narrowing before attribute access.
- If the repo configures mypy or pyright (`[tool.mypy]`, `[tool.pyright]`, `pyrightconfig.json`),
  its strictness is the bar; cite it.
- Truthiness: `if not value:` / `value or default` on values that can be `0`, `""`, `[]` or
  `False` legitimately. Require `if value is None:`.
- Impossible states: prefer `Literal[...]` / `Enum` over free strings, frozen dataclasses or
  Pydantic models with validators over dicts, `NewType` for IDs.
- Mutable default arguments (`def f(items=[])`).

## Error handling
- Bare `except:` and `except Exception: pass` / `continue`: swallowed errors.
- `except Exception as e: log(str(e))` that drops the traceback: use `logger.exception(...)`
  or pass `exc_info=True`.
- `raise NewError(...)` inside `except` without `from e`, which hides the cause.
- asyncio: `asyncio.create_task(...)` with no reference kept and no done-callback (exceptions
  vanish); `gather(..., return_exceptions=True)` whose results are never checked.
- Retries that catch everything, including `KeyboardInterrupt` / `SystemExit` or programming
  errors, instead of the transient error types.
- Context managers for resources (files, connections, locks) instead of manual close.

## Boundaries
- Route / handler / CLI entry parses and validates input; a service layer holds logic;
  data access sits in a repository or client module. Flag ORM or SDK calls in route
  handlers or templates.
- Sync blocking calls (`requests`, `time.sleep`, sync DB drivers) inside `async def`.
- N+1: queries or SDK reads inside loops or comprehensions; ORM lazy loading in a loop
  (use `select_related` / `joinedload` / batch reads); unbounded scans without pagination.
- Clients and connection pools created per call instead of per process.
- Import-time side effects (network, file I/O, reading secrets) in library modules.

Not applicable.

## Testing
- Framework: pytest; `tests/` directory, `test_*.py` files. Fixtures over setup/teardown
  classes; `pytest.mark.parametrize` for edge cases.
- Coverage: read the minimum from `--cov-fail-under` in `pyproject.toml`
  (`[tool.pytest.ini_options] addopts`), `setup.cfg`, `pytest.ini`, `tox.ini`, or
  `fail_under` in `[tool.coverage.report]` / `.coveragerc`. Cite the file and value.
- Async code tested with `pytest-asyncio` / `anyio`, not by calling `asyncio.run` in tests.
- Mocks patch where the name is looked up (`patch("module_under_test.client")`), not where it
  is defined.

## PR size exclusions
`uv.lock`, `poetry.lock`, `Pipfile.lock`, `pdm.lock`, `requirements*.txt` when generated by
`pip-compile` / `uv pip compile`, migration files generated by a tool with no manual edits.

## Sensitive paths
Auth and session code, token/signature verification, secrets loading, payment code,
database migrations, prompt construction that includes user input or personal data, code
that executes user-supplied input (`eval`, `exec`, `subprocess` with `shell=True`, `pickle`).
